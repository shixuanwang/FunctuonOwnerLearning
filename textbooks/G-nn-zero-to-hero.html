② 第一性原理：神经网络是什么（三件套）

任何神经网络——从 micrograd 的 7 节点图到 GPT-4 的万亿参数——只做了三件事。先说因果，后说术语。

1.1 函数逼近：网络 = 一个超大的可调函数

神经网络是一个带几十亿个旋钮（参数 W）的函数 f(x; W)。给一个输入 x（图像、文本、token 序列），输出一个预测 ŷ。"训练"就是反复拧旋钮，让 ŷ 接近真值 y。

为什么需要"可调"？因为现实世界的函数（"这张图是不是猫"、"这段话下一个字是啥"）写不出闭式解，只能让一个足够灵活的函数族去拟合。神经网络的灵活性来自两层：(1) 线性变换 y = Wx + b（旋钮）；(2) 非线性激活 y = tanh(x) / ReLU(x)（让函数能弯折，否则多层叠加还是线性）。只有线性+非线性交替堆叠，才能逼近任意函数（万能逼近定理）。

1.2 梯度下降：怎么拧旋钮（往 loss 减小的方向走）

需要一个数字告诉你"现在拧得多差"——损失 loss。然后问："每个旋钮该往哪个方向拧一格，loss 降最多？" 数学答案：每个参数的梯度 ∂loss/∂W 指向 loss 增大最快的方向，所以往反方向走一格：W ← W − lr · ∂loss/∂W。这就是梯度下降。lr（学习率）是步长大小——太大跨过谷底，太小训练太慢。

梯度下降的存在理由是"在高维空间里找方向"。神经网络有几十亿维参数，没法穷举，只能靠局部斜率贪婪地往低处走。反事实：不靠梯度，要么穷举（爆炸）、要么随机搜索（慢到不可用）。所有现代优化器（SGD/Adam/AdamW）都是"怎么估这个梯度、怎么走这一步"的工程改良。

1.3 链式法则：怎么算 ∂loss/∂W（这是反向传播的全部数学）

loss 是从 W 经过几十层 op 算出来的，没法直接求导。链式法则说：把整个过程拆成一串原子 op（加、乘、tanh、矩阵乘），每个 op 只需知道自己的"局部导数"，再沿计算图把上游梯度一路乘下去，就能算出 loss 对任何参数的导数。链式法则 = 反向传播 = autograd。这三者是同一件事的三个名字。

最反直觉的一点：反向传播不需要"重新跑一遍前向"。它用的是前向已经算好的数据值来算 local gradient（比如乘法 a*b 的 local gradient 对 a 就是 b 的值）。所以前向必须先跑完、data 就位，反向才能跑。这也是 PyTorch 要求你先 forward 再 backward 的根因。

③ micrograd：手写反向传播（吸烟刻肺）

整门课的原子内核。读不懂这一节，后面 makemore/gpt 的所有数学都是空中楼阁。

2.1 导数即"抖一下看响应"

最朴素的求导方法：把 x 抖一点点 h，看输出 y 变了多少。导数 = Δy/Δx = 每单位输入引起的输出变化。这就是斜率。代码：(f(x+h) − f(x)) / h，叫有限差分。

位置：micrograd/micrograd_lecture_first_half_roughly.ipynb cell-4，h=1e-6。

直觉：把函数想成山坡，你站在 x，往右挪一小步 h，看脚下高度涨了多少。Δy/h 就是这片小坡的陡度+方向。h 太大就跨过了别处的山头（不准），h 太小会撞浮点精度 floor（变成 0），所以 1e-6 是甜区。

Karpathy 故意用最朴素的前向差分而非中心差分（更准），因为目标是教学直觉不是数值最优。工程里几乎不用有限差分求导（慢且不准）——它的真正用途是验证反向传播的正确性（cell-11 的 lol() 就是干这个的）。任何写反向传播的 bug 都能被有限差分抓出来。
把 cell-4 的 h 从 1e-6 改成 1e-1，结果跳到 ~2.96（偏离真值 0）；改成 1e-20，结果炸成 0 或 nan。亲手感受"h 太大不准、太小被精度吃掉"的窗口。

2.2 计算图：把任何表达式拆成一串原子 op 的 DAG

要对复杂函数自动求导，必须先把它拆成"每一步都很简单"的链条——计算图是有向无环图（DAG）：节点 = Value（标量 + grad），边 = "谁是输入"。每个 op 必须是局部可微的：只知道自己的输入输出，就能算出"输入动一下我会怎么动"。整张图的导数 = 所有局部导数沿链路乘起来。

位置：micrograd_lecture_first_half_roughly.ipynb cell-7 的 Value 类。__init__ 存 data/grad/_children/_op/label；__add__/__mul__ 每次创建 out=Value(..., (self,other), '+')，把父节点塞进 _children。

直觉：把神经网络想成工厂流水线——每个工位只做一件简单事（加、乘、压扁），前一个的产出是后一个的原料。计算图就是工厂图纸。要追问"最终产品 L 里，原料 a 贡献了多少"——沿流水线从成品反着走回去，每个工位告诉你"我这一步放大/缩小了几倍"。

关键认知：每个节点只知道 (a) 自己两个父节点是谁、(b) 自己的局部求导规则。不需要知道整个网络。这就是反向传播能 scale 到百亿参数的原因——每个节点自治。读者第一次看会以为"反向传播要重新求一遍前向"，错——它用前向已经算好的 data 值算 local gradient，所以前向 data 必须先全部就位。

2.4 链式法则手推：local gradient × 上游梯度

要算 dL/da（L 对底层输入 a 的导数），但 a 离 L 隔着好几层 op，没法直接求导。链式法则：若 L=g(e) 且 e=f(a)，则 dL/da = (dL/de) · (de/da)。拆两段：(1) de/da 是 e 这个节点的局部导数（local gradient），只跟 e=f(a) 有关；(2) dL/de 是上游已算好的梯度，从 L 一路乘下来。两者相乘。

位置：cell-7 __mul__ 的 _backward：self.grad += other.data * out.grad。other.data 是 local gradient（d(a*b)/da = b），out.grad 是上游 dL/dout，两者相乘 = dL/da。手推全程见 cell-23~28。

2.5 为什么是 += 而不是 =（梯度累加）

当一个节点被多条路径使用（比如 b = a+a，a 在加法里出现两次），反向传播时 a 要收到来自两条路的贡献，必须累加。数学：多元链式法则 dL/da = ∂L/∂a|路径1 + ∂L/∂a|路径2。所以 _backward 里必须 self.grad += ...。

位置：cell-31 验证 a = Value(3.0); b = a+a; b.backward() 得到 a.grad = 2.0（而非 1.0）。Karpathy 本人在视频里栽过这个坑，micrograd_lecture_second_half_roughly.ipynb exp 的注释明说："NOTE: in the video I incorrectly used = instead of +=. Fixed here"。

这是 PyTorch optimizer.zero_grad() 必须每步调用的根源。PyTorch .backward() 默认也累加到 .grad——不 zero 就越积越大，方向全错。读者第一次学 PyTorch 经常忘记 zero_grad() 然后 loss 飞天，根因就是这条 += 规则。
cell-31 后 print(a.grad) 应该是 2.0。然后把 cell-7 __add__ 里的 += 临时改成 =，重跑，a.grad 变成 1.0（错的）。这个改动 + 重跑是理解累加最直接的实验。

2.6 拓扑排序：反向传播为什么是 O(n) 而不是指数爆炸

反向传播要按正确顺序调用每个节点的 _backward——保证"一个节点 _backward 时，它所有下游的 grad 都已算好"。DAG 的拓扑排序给出"从输出到输入"的合法顺序。复杂度 O(V+E)——每节点每边只访问一次。

位置：cell-7 的 backward()：build_topo 递归 DFS（visited 去重 + 后序 append），然后 self.grad = 1.0（种子），再 for node in reversed(topo): node._backward()。cell-16 打印了拓扑顺序供肉眼核对。

最反直觉的点：很多人以为反向传播会因"路径组合爆炸"很慢。错——拓扑排序保证每节点只被处理一次，梯度只沿父→子边回传一次，整张图线性时间。这也是为什么 6 层 transformer 也能秒级 backward——本质就是这种线性扫描的放大版。

2.7 闭环：从一个神经元到 MLP，前向→反向→更新的完整链路

有了 Value 的自动求导，把它拼成能学的网络：神经元 = tanh(Σwᵢxᵢ + b)，layer = 多个神经元并行，MLP = 多层串联。loss = MSE = (ŷ−y)²。训练循环三步：(1) 前向算 loss；(2) 反向把所有参数的 grad 填好；(3) p.data += −lr · p.grad（往梯度反方向走，因为梯度指向 loss 增大方向）。

2.8 PyTorch 交叉验证：micrograd = PyTorch autograd 的标量实现

micrograd 是教学玩具（标量、Python 循环、慢）。证明它数学正确最干净的方法：和 PyTorch 跑同一道题对答案。位置：second_half cell-13 用 PyTorch tensor 重建 cell-9 的神经元，结果 x1.grad=−1.5, w1.grad=1.0, x2.grad=0.5, w2.grad=0.0，和 micrograd 一字不差。

这证明 micrograd 不是"简化版近似"，而是和 PyTorch 同一个数学的标量实现。PyTorch 只是工程升级——tensor 向量化、CUDA 并行、fused kernel、内存复用。学完 micrograd 你已经懂了 PyTorch autograd 的内核机制。再看 PyTorch 的 .backward() 就是"同样的逻辑，向量化版本"。
w2.grad = 0.0 是为什么？因为 x2=0.0，乘法 local gradient 对 w2 是 x2.data = 0.0，所以 w2 这条边梯度=0。这叫"dead neuron"现象的雏形：ReLU 网络里若某神经元对所有样本都输出 0，它的权重永远收不到梯度，永久死亡。makemore/gpt 会再次撞上这个主题。

④ makemore：从 bigram 到 MLP（字符级语言模型）

把 micrograd 的"能学的函数"具体化到"能生成名字的语言模型"，并证明能力如何随结构升级而被一节节解放。

3.1 bigram 统计法：建模能力天花板 #1（只看一字）

最朴素的因果假设：下一个字符只依赖上一个字符（马尔可夫一阶）。把所有 (ch1, ch2) 共现次数统计进 27×27 表 N，行归一化得 P(下一个|上一个) = N[ch1,ch2] / N[ch1,:].sum()。

位置：makemore/makemore_part1_bigrams.ipynb：cell-8~10 填表 N；cell-23 P = (N+1).float(); P /= P.sum(1, keepdims=True)（N+1 是平滑，避免 log(0)）；cell-24 multinomial 采样生成（输出 mor./axx./minaymoryles. 这种不像名字的垃圾）。

keepdims=True 的广播维度是最大卡点：写成 P.sum(1) 不 keepdim，shape 变 (27,) 而非 (27,1)，P (27,27) / p (27,) 会沿对角线广播，结果概率全错。必须 keepdim=True 让除法沿列广播。读者第一次写必踩这个坑。
cell-26 把 for w in words 改成 for w in ['andrejq']，对比 (N+1) 平滑前后的 log_likelihood：平滑前会是 −inf，平滑后是有限大数。这让你亲眼看到"测试集出现训练没见过的 bigram 时，没平滑 loss 直接爆掉"。

3.2 从计数表到神经网络：one_hot@W = 查表

统计 N 是死表，不能梯度下降、不能平滑可控。把它改写成"矩阵乘法"——把输入字符 ix 编成 one-hot 向量（只在 ix 位为 1），那么 one_hot @ W 的结果就是 W 的第 ix 行（one-hot 起到"选择行"的作用）。于是 W 直接替代 N：W 的第 i 行 = "字符 i 后面接各字符的 log-counts"。再 exp() 还原成 counts，行归一化得概率——这三步合起来叫 softmax。

位置：part1 cell-30 xenc = F.one_hot(xs, 27).float()；cell-39 logits = xenc @ W; counts = logits.exp(); probs = counts / counts.sum(1, keepdims=True)（注释：last 2 lines together = softmax）。

这是全章节最关键的 aha：查表 ≡ 矩阵乘法。它让"频率统计"立刻变成可微、可梯度下降。读者会突然理解：one-hot 没有信息含量，只起"选择行"的作用；W 初始化成 randn 含负数也没事，因为 exp() 后正负都还原成概率。训练充分后 W ≈ log(N+1)。理解这一点，再看 MLP 的 embedding 查表、GPT 的 token embedding，全是同一件事的放大。

3.3 softmax + NLL：可优化的分类 loss

要量化"模型在这批数据上有多差"且可微。直觉：模型给正确下一个字符分配的概率 prob 越大越好。但直接最大化 prob 乘积（似然）会下溢，所以取 log 把乘变加 → 等价于最小化负 log 似然 nll = −Σ log prob → 最小化平均 nll/n。当输出层是 softmax 时，这个 loss 就叫交叉熵。

3.6 minibatch SGD + train/dev/test 三分

⑤ backprop ninja + 训练健康诊断

这一节是方法论：拿到一个训不动的网络怎么办？答案是先造仪表盘，再用仪表盘反推病根，对症下药。

4.1 诊断仪表盘一：tanh 饱和率（saturated%）

tanh 是 S 形压扁器：输入太大就压死在 ±1 平台上，平台处曲线几乎平，平=斜率 0=梯度 0。一个神经元饱和 = 这条信号通道断了；一整层饱和 = 死层。衡量指标：saturated% = mean(|h| > 0.97)，因为 |tanh|=0.97 时 1−h² ≈ 0.06，已吃掉 94% 的梯度。健康标准 <5%，理想 <2%。

位置：makemore/makemore_part3_bn.ipynb cell-15：(t.abs() > 0.97).float().mean() * 100。健康版输出 saturated ≈ 2%（layer2=2.78%, layer14=1.88%）。

复制 cell-15 在第 1000 步后打印 saturated%。然后把 Linear 初始化的 weight *= 1.0 改成 weight *= 3.0，重跑，看 saturated% 从 2% 跳到 50%+、loss 曲线变平——亲眼看到饱和=学不动。再改回 5/3（tanh 的 Kaiming gain）看回落。

4.2 诊断仪表盘二：激活分布直方图 + Kaiming 初始化

前向每过一层 Linear，方差被 fan_in 倍放大：Var(y) = fan_in · Var(W) · Var(x)。不补偿则 std 逐层指数膨胀（→ 后面层全饱和）；补偿过头则 std 逐层收缩（→ 全死在 0 附近）。Kaiming 给出刚好补偿的缩放：W ~ N(0, 2/fan_in)（ReLU）或 gain=5/3 for tanh。

位置：part3 cell-13 self.weight = torch.randn((fan_in, fan_out)) / fan_in**0.5（朴素 Kaiming）；part4 cell-8 W1 = randn * (5/3)/((n_embd*block_size)**0.5)（手写 Kaiming）。

为什么 tanh 的 gain 是 5/3 不是 1？因为 tanh 把方差也压扁了（tanh 在 0 附近斜率 1，整体平均斜率 <1），需要 W 比 N(0,1/fan_in) 大 5/3 倍才能补偿 tanh 的压缩，使 Tanh 输出方差守恒。这个 5/3 来自 1/E[tanh'(x)] 的积分，Karpathy 没推但提到了。

4.3 诊断仪表盘三：梯度分布 + grad:data ratio + ud 曲线

grad:data ratio = grad.std() / data.std() 衡量"这一步更新幅度相对参数本身大小"。太大 loss 震荡/发散，太小白白训练。健康值约 1e-3。ud = log10((lr·p.grad).std() / p.data.std()) 跟踪训练过程中这个比值随 step 演化，y=−3 黑线是健康基准。

位置：part3 cell-17 ratio；cell-18 ud 时序曲线。

ud 曲线是最有信息量的图。远离 −3（如 −5）说明 lr 太小学不动；远高于 −3（如 −1）说明 lr 太大要爆。这是比"看 loss 曲线"更早暴露问题的诊断工具——loss 还没明显发散，ud 已经告诉你 lr 不对。

4.5 BatchNorm：把每层激活强行拉回标准分布

4.6 梯度消失/爆炸：深层网络为什么训不动

反向传播是连乘：dh_L = dL · Π(每层局部导数)。每层局部导数 <1（饱和 tanh 的 1−h²≈0.05），10 层连乘 ≈0.05^10≈1e-13——前面层梯度比浮点下限还小，等于不学，叫梯度消失。每层 >1（未缩放 Linear 的 √fan_in≈31），10 层连乘 ≈31^10≈1e14——梯度爆成 nan，叫梯度爆炸。本质都是"连乘的指数效应放大任何偏离 1 的尺度"。

解法链：Kaiming 让 Linear 局部导数≈1；BN 把激活方差钉回 1 让 tanh 不饱和（局部导数≈0.64，配合 gain=5/3 补偿）；残差连接给梯度一条旁路（GPT 会用）。

常见误解："梯度消失是 sigmoid/tanh 的错，换 ReLU 就好了"。纠正：ReLU 也有 dead ReLU（负区间梯度=0），深层 ReLU 没 BN 一样会数值不稳。根因是连乘放大，根治要 BN/残差/合理初始化三件套，换激活只是缓解。

5.1 全局因果：GPT 到底在解什么

目标：最大化训练语料每个 token 的对数似然。loss = -(1/N)·Σ log P(x_{t+1}|x_1..x_t)。和 makemore_part1 bigram、part2 MLP 完全同一个 loss、同一个采样框架——区别只是"用什么把上文压缩成一个向量"。bigram：上文=前 1 字符；MLP：上文=拼接前 N 字符；GPT：上文=用 attention 让每个位置去挑它需要的历史信息。

读者最容易跳过 bigram 直接看 transformer，结果 attention loss 不降时不知道是 attention 写错了还是数据流写错了。Karpathy 故意先写 BigramLanguageModel 就是给你一个"已知正确的基线"——后面每加一个模块都能和它对比。

5.2 Self-Attention 的因果：为什么必须有 Q/K/V 三个角色

位置：nanoGPT model.py class Head：nn.Linear(n_embd, head_size, bias=False) 三个（key/query/value）+ register_buffer('tril', torch.tril(ones(T,T)))。forward 关键顺序：raw 分数 → 缩放 → mask → softmax → 乘 V。

最致命的误解：Q/K/V 是三种不同输入。错！它们是同一份输入 x 经过三个不同线性变换（Wq/Wk/Wv）投影出来的。原始 x 是"原始语义"，Q/K/V 是 x 戴上三顶不同帽子去完成三个任务（被别人查 K、去查别人 Q、贡献内容 V）。一个位置同时扮演三个角色。

5.3 为什么 softmax + 为什么 mask：把未来焊死

softmax 解决两个问题：(a) 把任意实数分数变成概率分布（非负、和为 1）—— wei 才能当加权系数；(b) 可微 + 放大最大者（winner-takes-most），让模型敢下决心。mask 解决：autoregressive 语言模型里，位置 t 绝对不许看 t+1..T（否则训练时作弊）。做法：把 tril（下三角=1）作为掩码，把上三角对应位置在 softmax 之前填 −inf，softmax 后变 exp(−inf)=0，权重为 0，贡献被掐死。

三个高频坑：(1) mask 必须在 softmax 之前用 −inf 填，不是 softmax 之后乘 0——因为 softmax 之后置 0 不会重新归一化，剩余权重和≠1，信息仍泄漏。(2) 最容易写反 tril 方向——torch.tril(ones(T,T)) 保留下三角（含对角线）= 位置 t 能看 0..t（含自己）。(3) dim=−1 还是 dim=−2——softmax 在最后一维（key 维）做，让"每个 query 对所有 key 的权重和为 1"。
把 Head 里的 mask 那行注释掉，重训：训练 loss 可能照常降，但生成时会"看到未来"（采样质量虚高），eval 时模型学到"作弊模式"。再把 scale 因子 √d_k 去掉：单层时 softmax 会饱和（一个 wei≈1，其他≈0），梯度消失，深了训不动。

5.4 为什么除以 √d_k：和 makemore tanh 饱和同源

Q·K 的每个分量是 d_k 个乘积之和。若 Q,K 分量 iid、均值 0 方差 1，则点积方差 = d_k（线性增长）。d_k=64 时点积标准差≈8，raw 分数动辄 ±8，进 exp 后变成 e^8≈2980 vs e^(−8)≈0，softmax 几乎 one-hot（梯度≈0）。除 √d_k=8 把方差拉回 1，让 softmax 工作在线性区，梯度健康。

新手常把它当"魔法常数"记。其实它和 part3 里"初始化时把 W 乘 1/√fan_in"是同一个原理：fan_in 越大、累加项越多、方差越大、必须缩放。把这两处连起来，神经网络初始化/归一化的整套逻辑就贯通了。本质就是"控制激活统计，防止 softmax/tanh 进饱和区"。

5.5 Multi-Head Attention：为什么不一个 head 吃完

单 head 的 wei 是 (T,T)，只能学到"一种匹配模式"。语言里同时存在多种关系：语法主谓、指代共指、长距离依赖。Multi-head = 把 n_embd 砍成 num_head 份，每份独立做 attention（学不同关系），最后 concat 回 (B,T,n_embd) 再过一个 Linear 融合。参数量 ≈ 单大 head（因为 head_size 变小），但表达力强得多。

位置：nanoGPT class MultiHeadAttention：self.heads = nn.ModuleList([Head(head_size) for _ in range(num_heads)]) + self.proj = nn.Linear(n_embd, n_embd)。forward：out = torch.cat([h(x) for h in self.heads], dim=-1); out = self.proj(out)。

两个坑：(1) 忘记 cat 之后加 proj 层。没 proj 的话多 head 输出只是"拼起来的多块独立信息"，没有"跨 head 综合"。(2) n_embd 必须被 num_heads 整除，否则 cat 维度对不上后面层。每个 head 维度小，反而逼它学"专精"——组合起来比一个臃肿的全才更聪明。

5.6 位置编码：attention 自己不知道"顺序"

attention 对输入是"集合"操作——Q·K 只看内容相似度，不看位置。把 [我,爱,你] 和 [你,爱,我] 在 attention 眼里如果不加位置信息是几乎等价的。补丁：给每个位置一个独立"位置向量"加到 token embedding 上。Karpathy 版用学习式：wpe = nn.Embedding(block_size, n_embd)。

位置：nanoGPT class GPT.__init__：self.wte = nn.Embedding(vocab_size, n_embd) + self.wpe = nn.Embedding(block_size, n_embd)。forward：tok_emb = self.wte(idx); pos_emb = self.wpe(torch.arange(T)); x = tok_emb + pos_emb。两个 embedding 形状都是 (T, n_embd)，相加就是把"这个词是什么"和"这个词在第几位"融合。

block_size 限制：wpe 只预定义了 block_size 个位置，超过无法外推（学习式的硬伤）。这也是为什么后面 nanoGPT 要讨论 ALiBi/RoPE 等相对位置编码。读者先把"为什么需要位置编码"焊死，再去看那些进阶方案。

⑦ 从零搭 GPT（decoder-only transformer）

把 §5 的零件像乐高一样叠成一个完整 GPT，跑出莎士比亚风格文本。

6.1 FeedForward：attention 之后必须有的"逐位置消化"层

attention 输出是"加权聚合的他人信息"，但每个位置拿到这些信息后需要"自己消化、推理"。FeedForward：x → Linear(n_embd, 4·n_embd) → ReLU/GELU → Linear(4·n_embd, n_embd)。中间扩展 4 倍（瓶颈→宽→瓶颈），让模型在高维空间做非线性变换再压回。

位置：nanoGPT class FeedForward：nn.Sequential(nn.Linear(n_embd, 4·n_embd), nn.ReLU(), nn.Linear(4·n_embd, n_embd))。在 Block 里 self.ffwd = FeedForward(n_embd)。

误以为 FFN 可有可无、attention 才是主角，是致命误解。实验证明去掉 FFN 后模型能力断崖式下降。attention 负责"信息路由"（谁和谁通信），FFN 负责"信息变换"（把路由来的信息加工成新表示），缺一不可。原论文标题"Attention is All You Need"其实有点误导，FFN 和 residual 同样关键。

6.2 Residual Connection：让深网络能训的"高速公路"

标准前向 y = F(x)。残差 y = x + F(x)。反向时 dy/dx = I + dF/dx，恒等项 I 保证梯度可以"无损"回流到浅层，不会因连乘消失。堆叠 N 层残差，梯度从末层到首层有 N 条"直通"路径。

位置：nanoGPT class Block.forward：x = x + self.sa(self.ln_1(x)); x = x + self.ffwd(self.ln_2(x))。两处 + x 就是残差。

和 makemore_part3 讲的"深网络难训"是直接对症下药。盖楼不搭脚手架，10 层就塌（梯度消失/爆炸）。残差是"脚手架+电梯"：每层楼（F）盖在原有楼（x）旁边，电梯（+x）保证你随时能从顶楼直达底楼。Pre-LN（x + Sublayer(LayerNorm(x))）比 Post-LN（LayerNorm(x + Sublayer(x))）更稳，是现代实现的共识。

6.3 LayerNorm：把每个样本的特征归一（vs BatchNorm）

对单个样本单个位置的特征向量 x∈R^n_embd：减均值、除标准差、再仿射变换 γ·(x−μ)/σ + β。在每个 (B,T) 位置独立地对 n_embd 维做归一。

数据流：idx(B,T) → tok_emb+wpe → [Block×N] → ln_f → lm_head(Linear(n_embd, vocab)) → logits(B,T,vocab)。Block = [LN→MHA→+] → [LN→FFN→+]。loss = F.cross_entropy(logits.view(B·T, vocab), idx.view(B·T))，标签是"右移一位"（数据加载：x = idx[:,:-1], y = idx[:,1:]）。decoder-only = 只有 mask 的 self-attention，没有 cross-attention。

6.5 训练循环：让这一切真的跑起来

优化器用 AdamW（Adam + weight decay）。学习率 3e-4（"magic number"，对小型 transformer 几乎万能）。每个 step：xb,yb = get_batch('train') → logits,loss = m(xb,yb) → optimizer.zero_grad() → loss.backward() → optimizer.step()。

跑完整训练（n_layer=6, n_head=6, n_embd=384，10k 步），loss 应降到 ~1.5，生成出的莎士比亚风格文本可读。把 n_layer 从 6 调到 1，loss 降到 ~2.x 就停滞；调到 12（参数翻倍），loss 更低但更慢——手感到"深度换能力"的曲线。

⑧ GPT-2 + Tokenizer + 微调（真能训出模型）

这一节是"落地段"：从研究 demo 变成可加载、可复现、可定制的真实模型。所有 code_map 指向外部仓库（nanoGPT / minBPE / build-nanogpt）。

7.1 GPT vs GPT-2 工程化差异

GPT-2 工程化核心 = (1) 把每层参数命名固化成稳定 key（如 'transformer.h.0.attn.c_attn.weight'）；(2) 给出 config（n_layer/n_head/n_embd/vocab_size）描述形状；(3) 用 OrderedDict 保存 state_dict。数学上没新东西，关键是"模型拓扑的序列化契约"。

位置：外部仓 nanoGPT/model.py 的 GPTConfig + GPT；nanoGPT/gpt2.py 把 OpenAI 原版 tf checkpoint 转成 PyTorch state_dict。

最坑的工程细节：OpenAI ckpt 用 TensorFlow 的 Conv1D（weight shape [n_in, 3·n_embd]），PyTorch nn.Linear 存 [out, in] = [3n, n] 布局相反，必须 transpose。c_attn 一个矩阵 [n, 3n] 也要拆成 q/k/v 三份并 transpose，否则 attention 算的是错的相似度——shape 对得上不代表语义对。

7.2 BPE tokenizer：字符串 ↔ token 整数的翻译器

语言模型只懂整数索引，不认字。BPE 因果链：(1) 初始词表 = 256 字节（永不 OOV）；(2) 反复找语料里出现最频繁的相邻 token 对，合并成新 token 加进词表；(3) 合并 N 次后词表 = 256 + N（GPT-2 是 256+50000+1 特殊符 = 50257）。每合并一次记一条 merge rule（按顺序优先匹配）。

三个核心卡点：(1) 为什么词表初始化用 256 字节而不是 Unicode 码点——字节永远 ≤256 种，不会 OOV；Unicode 码点 14 万种放不下。(2) merge 规则的"顺序优先级"——encode 时必须按训练时的合并顺序贪心匹配。(3) 为什么模型不会拼写/不会数字母——根因就是 BPE 把词切成不可见子词，模型根本看不到单字符。

7.3 自回归生成：为什么是"采样"不是"argmax"

如果总取 argmax（最大那个），就是确定性解码，会陷入循环（"I am I am I am"）。所以按 logits→softmax→概率→按概率抽样。三个旋钮：(1) temperature T：logits/T 后再 softmax，T<1 锐化、T>1 平滑，T=0 退化为 argmax。(2) top-k：只在概率最高 k 个里采样。(3) top-p（nucleus）：取累计概率刚好超过 p 的最小 token 集合。

位置：nanoGPT/sample.py 和 build-nanogpt 的 generate：logits = logits[:,-1,:] / temperature; if top_k: topk 过滤; probs = softmax(logits); idx_next = multinomial(probs, 1); idx = cat(idx, idx_next)。

用同一 prompt，temperature=0.0 跑 5 次看输出完全一样（等价 argmax）；temperature=1.0 跑 5 次看每次不同；0.7 + top_k=40 是 GPT-2 经典组合。把 top_k 设 1 退化为贪心，观察复读循环。

7.4 加载预训练权重：strict load 与 key 映射的脏活

流程：① 实例化 model（随机权重）；② model.state_dict() 拿到自己的 key→tensor；③ ckpt 也是 key→tensor；④ 逐 key 比对 name 和 shape；⑤ 对不上的报错（strict=True）或忽略（strict=False）。GPT-2 特殊点：OpenAI 把 qkv 合并成一个 c_attn [n_embd, 3·n_embd]，必须 reshape+transpose 转成 nanoGPT 的三个 q/k/v_proj。

三个误解要破除：(1) load_state_dict(strict=True) 通过 ≠ 万事大吉——strict 只保证 name+shape 对得上，不保证语义（把 q_proj 权重塞给 k_proj shape 也对，但模型错了，loss 会爆）。(2) c_attn 不能直接 load，必须拆 q/k/v + transpose。(3) LayerNorm 的 γ/β 必须加载，漏掉会导致前几层激活分布崩。

7.5 微调（finetune）：在冻结架构上用小学习率继续训

流程：加载预训练 ckpt → 换/加任务头 → 用你的小数据集 + 小 lr（预训练的 1/10~1/100）继续 forward+backward+step。两个变体：(1) 全参微调：所有参数更新，风险是灾难性遗忘；(2) LoRA 等 PEFT：冻结原权重，注入低秩 A·B 矩阵只训它们，参数量降到 1% 以下。

位置：build-nanogpt（github.com/karpathy/build-nanogpt）的 train_gpt2.py 展示从预训练 ckpt 续训的标准循环；nanoGPT README 有 finetune 指引（改 data 路径 + 降 lr + warmup）。

lr 必须小——大步子会把通识记忆冲乱（灾难性遗忘），就像让博士去学拧螺丝，结果把博士知识全忘了只会拧螺丝。LoRA 像"不改正文，只在页边贴便签"，便签很便宜（低秩）但够用——因为微调时权重变化本来就是低秩的（实证发现）。这是 2023 年后大模型微调的主流方案。

⑪ 关键数学附录

11.1 链式法则（反向传播的全部数学）

若 L = g(e) 且 e = f(a)，则 dL/da = (dL/de) · (de/da)。

  • de/da = e 节点的 local gradient（只跟 f 这一步有关）
  • dL/de = 上游已算好的梯度（从 L 一路乘下来）
  • 两者相乘 = dL/da

多路径累加（多元链式法则）：当 a 通过多条路径影响 L 时，dL/da = Σ_path (∂L/∂a)|_path。这是 += 的数学根源。

11.2 softmax + 数值稳定

softmax(x)_i = exp(x_i) / Σ_j exp(x_j)。把任意实数变成概率分布（非负、和为 1）。

数值稳定技巧：softmax(x) = softmax(x − max(x))，对所有 logits 同加一个常数不变，所以减去行最大值后最大值变 0，exp 不会溢出，结果概率完全不变。这就是 makemore part4 forward 里 logit_maxes = logits.max(1, keepdim=True); norm_logits = logits − logit_maxes 的因果。

反向：dsoftmax/dx 的雅可比矩阵非对角元是 p_i·p_j，对角元是 p_i·(1−p_i)。但和 cross_entropy 合一后简化成 dlogits = softmax(logits) − onehot(Y); /=n——这是工程上的 fused 反向公式。

11.3 交叉熵 / NLL（最大似然 → 最小 NLL 四步等价）

  1. 最大化似然：max Π P(y_i|x_i)（独立事件概率乘积）
  2. 等价于 最大化 log 似然：max Σ log P(y_i|x_i)（log 单调，乘变加，不下溢）
  3. 等价于 最小化负 log 似然：min −Σ log P(y_i|x_i)（约定 loss 越小越好）
  4. 等价于 最小化平均 NLL：min −(1/N) Σ log P(y_i|x_i)（独立 batch 大小）

当输出层是 softmax 时，这个 loss 就叫交叉熵。NLL 和交叉熵数值完全一样，只是推导视角不同（MLE vs 信息论）。随机基线：loss = log(vocab_size)（如 ln(27)≈3.30, ln(65)≈4.17）。

11.4 scaled dot-product attention

Attention(Q,K,V) = softmax(Q·K^T / √d_k) · V

  • Q,K,V 由同一份 x 经 Wq/Wk/Wv 投影
  • Q·K^T 算两两相似度，shape (B, T, T)
  • /√d_k 控制方差，防止 softmax 饱和（同 makemore tanh 饱和原理）
  • causal mask 在 softmax 前把上三角填 −inf
  • softmax 后权重 wei (B,T,T)，再乘 V 得 (B,T,head_size)

11.5 Kaiming 初始化

W ~ N(0, gain²/fan_in)。gain=√2 for ReLU，gain=5/3 for tanh。

因果：前向 y = x·W，Var(y) = fan_in · Var(W) · Var(x)。要让 Var(y) = Var(x)（方差守恒），需 Var(W) = 1/fan_in。再乘 gain² 补偿激活函数对方差的压缩（ReLU 砍一半需 ×2，tanh 压缩约 1/(5/3)² 需 ×(5/3)²）。
