③ 架构质量（产品 / 技术 / 数据 三架构）

3.1 产品架构：以终态倒推但叙事>交付

优点：以"发版准出 Gate"为终态倒推 4 阶段 × 4 角色 × 5 闭环的写法是资深 PM 思维；§0.3 北极星选"准出报告自动覆盖率"而非任务数/PV 是反虚荣指标自觉；IA 重排（按工作场景而非数据维度）有明确诊断依据。

4 类硬伤：
  1. 北极星 0/NaN 不可短期观测：分子=准出报告数（Gate 引擎 0 行）；分母=算法包发版总数（grep release_at/released_at/release_ts 全仓 0 命中，平台没有"记录发版事件"的源系统）。当前值=0%，且 P0 路线图没有"做分母"的工作项。launch 后第一年无法证明价值增长 → 管理层第二季度砍预算。
  2. Gate 0 override 0 RBAC 0 认证：grep override/紧急放行/bypass/force pass/exempt 全空，grep requireAuth/JWT/passport/session/currentUser 全空。backend/src/config 无任何 auth 中间件。SonarQube 式硬阻塞没有 override 通道（Advisory → Soft → Hard 三阶段）+ DRI 签字 + 工单留痕 + 事后回归，必然被研发绕过或管理层一次性关停。这是项目第一杀手。
  3. "5 闭环"叙事与 P0 落差：A（HiL）+ B（实时性能）真闭合；C（故障-处置）vehicleSync.ts:11 单向无回写；D（模型回归）三段全 danger；E（数据质量告警回流）未交付。但 §2 mermaid 把它们都画成完整闭环。即 P0 launch 时对外宣称 5/5 实际 2.5/5。
  4. §2.4 与 §10 自相矛盾：§2.4 自己写"回归判定引擎与 Quality Gate 共享 catalog 与判定逻辑，应在 P0 一起做"，§10 把回归引擎排 P1。同一份 PRD 内部直接矛盾。

3.3 数据架构：行业领先的"设计级"，运行级待激活

真正工业级的设计：

  • 血缘契约：authority_pg_v3.sql:48-96 四重 64 位 hex sha256 CHECK（fragment_manifest / fragment_source_evidence / logical_fingerprint / evidence）+ IMMUTABLE 函数 + immutable trigger + fragment_revision 幂等链 + UNIQUE(evidence_sha256)。这是 PRD §5.5 的实打实落地，不是 PPT 血缘。
  • generation 原子发布：stage 表 TTL 3d reader 不可见 → 32 DQ Gate publication-blocking（已 python -c 验证 expected_gates 数量=32）→ PG fence 唯一约束抢占 → 6 表 REPLACE PARTITION FROM stage → reader 通过独立 PG activation 切换可见性。schema 层把"部分发布/重复发布/脏发布"物理上变不可能。
  • source_registry 身份键：物理身份（含 seq_num/jmq_offset）与业务身份（dag_business_identity_key_v2）精确分离，ETL 用 any() + payload_versions 冲突检测实现可解释去重（onboard_qc_1s_ads_etl_v2.sql:17-46），比 argMax 黑盒兜底更可审计。
  • CK 分层权衡：ODS 1Hz 不落 OSS parquet 改落 CK ReplicatedMergeTree（文档说 OSS 但代码没改完，见 §2 之 1）；(dt,generation) 复合分区 + TTL 分级 + cityHash64(vin) 分布键。
三方共同盲点（最重大发现）：warehouse/etl/onboard_qc_1s_generation_publish_v2.sql:1 第 1 行注释明写 "v2 generation publication skeleton. Repository-only; execution is disabled."，且 grep -r generation_publish ops/ deploy/ scripts/ 无任何 cron/Argo 调用——即数据架构师盛赞的"32 DQ Gate + PG fence + 6 表 REPLACE PARTITION + immutable trigger + sha256 CHECK"是设计态非运行态。等同于 §8.3 的 prod-shadow 问题但更隐蔽（prod-shadow 至少 PRD 自承阻断，generation publish 的 execution=disabled 三方都没看到）。此发现直接动摇 §5.5/§5.6"血缘契约已落地"全部论断的可信度。

4.2 关键反事实（为何这么选）
